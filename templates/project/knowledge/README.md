# Project Knowledge

This is the knowledge router for `{{PROJECT_NAME}}`. Start here when deciding which project memory to load.

## Default Entries

| Entry | When to read | Path |
| --- | --- | --- |
| Agent memory | Complex tasks, cross-session work, project conventions, handoff | `agent-memory/AGENT_MEMORY.md` |
| Workflow playbook | Choosing work shape, validation, multi-agent use, closeout | `agent-memory/WORKFLOW_PLAYBOOK.md` |
| Task state | Resuming active or long-running work | `agent-memory/task_state/` |

## Add Project Knowledge Areas

Add a new knowledge area only when it has a stable purpose. Examples:

- `architecture/`
- `product/`
- `research/`
- `operations/`
- `data-sources/`

Each area should have a compact entry file and should be linked from this README.

## Boundaries

- Keep memory concise and useful.
- Store stable knowledge, not raw clutter.
- Keep secrets and personal access data out of the repository.
- If a fact may be stale, record the source and the date checked.
